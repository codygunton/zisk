# Zisk Witness Generation Implementation Plan

## Executive Summary

### Problem Statement
The current witness generation uses airbender (32-bit RV32IM emulator) to execute zksync-os and capture oracle reads. When replaying this witness on Zisk (64-bit RV64IM), there's a fundamental architecture mismatch:
- Airbender witness contains u32 values with response_len counts based on 32-bit reads
- Zisk's 64-bit guest expects different response_len values and u64 data

This mismatch causes query sequence divergence, leading to crashes when the 64-bit guest reads incorrect data from the witness.

### Proposed Solution
Generate the witness using Zisk directly instead of airbender. Since the same architecture produces and consumes the witness, there's no conversion needed - the oracle protocol matches exactly.

### Technical Approach
1. Create a bridge between zksync-os's `ZkEENonDeterminismSource` oracle and Zisk's `OracleCallback` interface
2. Add a witness capture mode that records all oracle reads as u32 values
3. Integrate into the existing test infrastructure as an alternative to airbender

### Expected Outcomes
- Witness generated by Zisk can be replayed on Zisk without conversion
- Query sequences match exactly between generation and replay
- Block execution completes successfully including ZK_PROOF_DATA_INIT phase

## Goals & Objectives

### Primary Goals
- Enable witness generation using Zisk emulator for 64-bit zksync-os execution
- Eliminate 32-bit/64-bit oracle protocol mismatch

### Secondary Objectives
- Maintain compatibility with existing airbender witness generation (don't break it)
- Keep the same witness file format (hex-encoded u32 values)
- Minimal changes to existing oracle infrastructure

## Solution Overview

### Approach
Create a thin bridge layer that adapts zksync-os's oracle interface to Zisk's callback-based interface, with witness capture built in.

### Key Components

1. **ZiskOracleBridge** (new): Adapts `ZkEENonDeterminismSource` to Zisk's `OracleCallback`, capturing reads
2. **zisk_witness_runner** (new): Library function to run Zisk with live oracle and capture witness
3. **chain.rs modification**: Add Zisk path alongside existing airbender path

    ```rust

    use zisk_core::mem::{OracleCallback, OracleOp};
    ```
  - Implements:
    ```rust
    /// Captures oracle reads into a Vec<u32> while forwarding to underlying oracle.
    pub struct WitnessCapture<F>
    where
        F: FnMut(OracleOp) -> u64 + Send,
    {
        inner: F,
        reads: Arc<Mutex<Vec<u32>>>,
    }

    impl<F> WitnessCapture<F>
    where
        F: FnMut(OracleOp) -> u64 + Send,
    {
        pub fn new(inner: F) -> Self;
        pub fn get_reads(&self) -> Arc<Mutex<Vec<u32>>>;
        pub fn into_callback(self) -> OracleCallback;
    }

    /// Create a witness-capturing oracle callback from a read/write function pair.
    pub fn create_witness_capture_callback<R, W>(
        read_fn: R,
        write_fn: W,
    ) -> (OracleCallback, Arc<Mutex<Vec<u32>>>)
    where
        R: FnMut() -> u32 + Send + 'static,
        W: FnMut(u32) + Send + 'static;
    ```
  - Behavior:
    - On `OracleOp::Read`: call inner, cast result to u32, push to reads vec, return as u64
    - On `OracleOp::Write(val)`: call inner with val as u32, return 0
  - Exports: `WitnessCapture`, `create_witness_capture_callback`

      ```rust
      use risc_v_simulator::abstractions::non_determinism::NonDeterminismCSRSource;
      use std::sync::{Arc, Mutex};
      use std::cell::RefCell;
      ```
    - Implements:
      ```rust
      /// Bridge between ZkEENonDeterminismSource and Zisk's oracle callback interface.
      /// Captures all reads into a witness vector.
      pub struct ZiskOracleBridge {
          oracle: RefCell<ZkEENonDeterminismSource<DummyMemorySource>>,
          witness: Arc<Mutex<Vec<u32>>>,
      }

      impl ZiskOracleBridge {
          pub fn new(oracle: ZkEENonDeterminismSource<DummyMemorySource>) -> Self;
          pub fn get_witness(&self) -> Arc<Mutex<Vec<u32>>>;

          /// Called by Zisk emulator on CSR write
          pub fn write(&self, value: u32);

          /// Called by Zisk emulator on CSR read, captures to witness
          pub fn read(&self) -> u32;

          /// Convert to Zisk OracleCallback
          #[cfg(feature = "zisk-witness")]
          pub fn into_callback(self) -> ziskemu::OracleCallback;
      }
      ```
    - Note: Uses `RefCell` because `NonDeterminismCSRSource::read()` takes `&mut self`
      but we need shared access. Single-threaded execution makes this safe.

    ```rust
    #[cfg(feature = "zisk-witness")]
    pub fn run_block_generate_witness_zisk<const FLAMEGRAPH: bool>(
        oracle: ZkEENonDeterminismSource<DummyMemorySource>,
        elf_path: &str,
    ) -> Vec<u32> {
        let bridge = ZiskOracleBridge::new(oracle);
        let witness_ref = bridge.get_witness();
        let callback = bridge.into_callback();

        // Run Zisk emulator with the oracle callback
        let mut emu = ziskemu::ZiskEmulator::new();
        let elf_data = std::fs::read(elf_path).expect("failed to read ELF");

        emu.run_with_oracle(
            vec![], // no stdin input
            &ziskemu::EmuOptions::default(),
            None::<Box<dyn Fn(ziskemu::EmuTrace)>>,
            Some(callback),
        );

        // Extract captured witness
        let witness = witness_ref.lock().expect("witness lock").clone();
        witness
    }
    ```

## Alternative Approaches Considered

### A. Modify Replay64Oracle to handle protocol correctly
- **Rejected**: Doesn't solve fundamental issue of different query sequences between 32-bit and 64-bit
- The 64-bit guest makes different decisions based on data, leading to query order divergence

### B. Make airbender support 64-bit
- **Rejected**: Major undertaking, airbender is specifically designed for RV32IM
- Would require significant architectural changes

### C. Generate witness on-demand during Zisk execution
- **Considered but deferred**: Would require live oracle connections during replay
- Current approach of pre-computing witness is simpler and matches existing infrastructure

## Dependencies

### External Dependencies
- ziskemu must be importable as a library from zksync-os test crate
- Requires relative path dependency or git dependency in Cargo.toml

### Build Dependencies
- Feature flag `zisk-witness` controls whether Zisk path is compiled
- Allows gradual rollout without breaking existing airbender path
